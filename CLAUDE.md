# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Living Library of Trees" — a metaLAB visualization of Arnold Arboretum plants and the curators who annotated them. SvelteKit 2 + Svelte 4 (not runes: uses `export let`, `$:`, `createEventDispatcher`), D3 for projection/zoom, fully static (prerendered, `adapter-static`), deployed to GitHub Pages.

The canonical app repository (`origin`) is `sinanatra/arboretum`.
`main` contains the current app and is the active development branch.

## Commands

```bash
npm install
npm run dev                          # dev server
npm run build                        # static build into docs/ for /arboretum
npm run preview
npm test                             # node tests in scripts/
npm run sync:data                    # refresh static/data from ../arboretum-data
```

- `svelte.config.js` defaults production `paths.base` to `/arboretum`; `BASE_PATH` overrides it. The static adapter writes pages and assets into tracked `docs/`. GitHub Pages publishes `main:/docs`. Rebuild and commit `docs/` with source updates. Generated `docs/data/` JSON is public; the pipeline stays in the private data repository.
- Map calculation audit: `node scripts/audit_visualization.mjs`. Its report goes to git-ignored `reports/`. No linter or type-checking is configured.
- Both `package-lock.json` and `yarn.lock` are committed; `.npmrc` sets `engine-strict=true`.

## Data

The data pipeline, its raw-data reference, the CSV exports and the source audit live in the private repo `rodighiero/arboretum-data`, normally checked out next to this one as `../arboretum-data`. The private BG-BASE export (`raw-data/`) lives only there; never copy it into this repo.

`static/data/plants.json`, `relations.json` and `curators.json` are a git-ignored local copy of that repo's `data/`. Dev and build sync automatically. Don't edit or regenerate them here: rebuild and commit in `arboretum-data`, then run `npm run sync:data`. The sync refuses uncommitted data and writes `static/data/source.json` with the source commit and SHA-256 checksums; `scripts/test_synced_data.mjs` fails if the files no longer match it.

## Architecture

Aliases (in `svelte.config.js`): `@components` → `src/lib/components`, `@lib` → `src/lib`. There are no stores; state lives in `src/routes/+page.svelte` and flows down via props, back up via dispatched events.

### Main view (`/`)

`src/routes/+page.svelte` fetches everything client-side in `onMount` and renders nothing until all of it is loaded:

- `data/plants.json` — one record per plant (`PLANTID`, `ACC_YR`, `last_date`, `CONDITION`, `STATUS`, `LATITUDE`, `LONGITUDE`, `COORD_SOURCE`, `NAME`, …)
- `data/relations.json` — `[{ CuratorName, From, To, PlantDates: [{ PlantID, Date }] }]`; `From`/`To` is the curator's active window over all their records (used for the list's time sorts and axis), while `PlantDates` holds only mapped plants
- `data/curators.json` — curator bios (`Name`, `Information`)
- `map/render.json` — prepared projection parameters and batched background paths at the fixed 1000×800 extent; generated by `npm run prepare:map` automatically before dev/build

It then renders:

- `Viz.svelte` — the SVG map. Projects each plant, snaps it into a selectable 5, 10, or 20 meter grid cell, and aggregates each cell into one circle (radius per `sizeMode`, color per `colorMode`). Owns d3-zoom; the transform is applied to a single `<g>` wrapping `BaseMap` and the dots. When a curator is selected, nodes containing that curator's plant IDs use 0.7 fill opacity; the rest stay at 0.1.
- `BaseMap.svelte` — renders the prepared background as one SVG path per type. `scripts/prepare_map.mjs` reads `grid_3px.geojson` for the original projection and `grid_5px.geojson` for tiles; the original files remain available to audits and map authoring. `node --test scripts/test_prepared_map.mjs` verifies projection, tile geometry and disjoint batching.
- `Panel.svelte` → `Header`, `Legend`, `CuratorTimeline` — sidebar. Clicking a curator dispatches `select` → Panel dispatches `curatorChange` with that curator's record → `+page.svelte` passes it to `Viz` as `selectedCuratorData`.

Plant ↔ curator joins are done on lower-cased plant IDs (`PLANTID` vs `PlantID`); curator ↔ bio joins on lower-cased name.

Dot color modes and their palettes live in `src/lib/colors.js` (`COLOR_MODES`); `Viz` colors cells from it and `Legend` shows the current mode's entries. Numeric modes use the cell's average year; categorical modes use its most common value and an explicit Mixed / tied category when there is no unique winner. Ties never depend on input order. Mean elapsed years since accession are computed before the 100-year display cap, with a fixed 2012 reference year. Other size modes use area-proportional scaling with a minimum visible radius and documented caps. The legend and sidebar explain cell aggregation, full-window timelines versus mapped counts, and per-observer normalization. A selection status reports filtered matching plant records and zero results.

### Base-map generation tool (`/create-map`)

`src/routes/create-map/+page.svelte` + `generatePixelMap.svelte` is an in-browser authoring tool, not part of the public visualization. It loads the raw OSM export `static/map.geojson`, rasterizes it into grid cells with Turf (streets are buffered lines; areas are classified park/water/other), and downloads the result as `grid_{N}px.geojson`. Those files are then placed manually in `static/map/`. The Overpass query that produces `map.geojson` is in `README.md`.

### Gotchas

- Data URLs prepend `base` from `$app/paths` to `/data/…` and `/map/…`. Do not use bare root URLs or resolve against the current page: requests must work at both `/` and `/arboretum`, including nested routes with trailing slashes.
- `+layout.js` enables `prerender` and `ssr`, so components that touch `window` at module/init time (e.g. the default props in `generatePixelMap.svelte`) can break the build if rendered server-side.
- Everything in `static/` ships in the build, so don't leave unused datasets there. `static/map.geojson` (the raw OSM export) is only used by `/create-map`.
